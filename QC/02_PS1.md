# PS1: Quantum Circuit Debugger and Hidden-String Solver

**Level:** Beginner.

**Core idea:** Implement quantum computation yourself without quantum computing libraries.

## Problem statement

Quantum programming tools often hide the calculations behind a circuit. A newcomer can run a program and see a result without understanding how individual gates changed the state.

Build a small quantum circuit simulator with a step-by-step inspection interface. Users should be able to construct circuits, apply gates to selected qubits, inspect amplitudes and probabilities, and measure results. Use the same simulator to implement the Bernstein–Vazirani algorithm, which recovers a hidden binary string through a special query operation.

The application must calculate behavior from the supplied gates and support user-created circuits, rather than display prewritten results for a few examples.

## Understanding the hidden-string problem

Imagine a hidden string such as `1011`. The solver cannot read it directly. Instead, it can access a function called an **oracle**.

For an input string `x`, the oracle returns the parity of the positions where both `x` and the hidden string `s` contain `1`. Parity is `0` for an even count and `1` for an odd count:

```text
f(x) = (s[0] × x[0] + ... + s[n-1] × x[n-1]) mod 2
```

A classical solver can query one position at a time. The quantum algorithm uses interference to recover the string with one application of the quantum oracle in the ideal query model. That oracle can contain several gates; simulating it on a laptop still requires ordinary computation.

The application knows the string when constructing the oracle. The solver must obtain its answer from circuit measurements.

## Required functionality

### Multi-qubit circuit simulation

Support registers of two to six qubits, initialized to the all-zero state. Store the joint state as amplitudes for every possible binary outcome. The six-qubit limit includes any helper qubit.

Implement X, H, Z, and CNOT gates. Single-qubit gates must work on any selected qubit, and CNOT must accept distinct control and target qubits. Update the joint state rather than simulating each qubit independently.

Allow users to enter an ordered gate sequence, execute it one step at a time, run the full circuit, and reset. A command-line interface is sufficient if intermediate states are readable.

### Circuit inspection and measurement

After each operation, display the gate, affected qubits, nonzero amplitudes, and probabilities with binary labels. Define which displayed bit corresponds to each qubit.

Support measuring a selected qubit or the full register. For a single-qubit measurement, calculate probabilities from the joint state, discard incompatible components, and normalize the remaining state. Subsequent measurements must reflect that change.

Support repeated runs with a freshly initialized circuit and display a result histogram. Include a random seed option for reproducible demonstrations.

### Entanglement demonstration

Include a two-qubit experiment that applies H followed by CNOT to create a Bell state. Show the joint probabilities before measurement and how measuring one qubit changes the remaining state. Explain why this differs from two independently randomized bits.

### Hidden-string solver

Accept hidden strings of length two to five. Construct the Bernstein–Vazirani circuit using the input qubits, one helper qubit, and your simulator's gate operations.

Build the oracle from the supplied string: each `1` selects a CNOT from its input qubit to the helper. Keep oracle construction separate from the solver. The solver receives the oracle operation and string length; it must not read the string or inspect the oracle's gate list to extract the answer.

Display the circuit stages, recovered string, measurement distribution, and oracle-call count. Include a classical solver that queries `f(x)` with one `1` at a time. Report its query count separately from the quantum circuit's gate count.

For example, a hidden string `1011` should be recovered as `1011` through measurement in an ideal run. Copying the input into the output is not an implementation of the algorithm.

## Implementation boundaries

Use Python. Standard-library mathematics, random sampling, and complex numbers are allowed. NumPy may be used for arrays and basic arithmetic, but gate application, state updates, measurement, and algorithm construction must be your own code.

Do not use Qiskit, Cirq, PennyLane, quantum simulation packages, or prebuilt implementations of the algorithm. Quantum hardware and cloud services are not required.

Handle invalid qubit indices, malformed strings, unsupported gates, and invalid repetition counts with clear messages. Account for floating-point rounding when displaying and sampling probabilities.

## Final deliverables

- **A GitHub repository** containing the working simulator, circuit inspection interface, Bell-state demonstration, and hidden-string solver.
- **A detailed README** explaining the problem, prerequisite concepts, state representation, gates, measurement and collapse, bit-order convention, and the hidden-string algorithm. Include installation instructions, dependency versions, commands for custom circuits and both demonstrations, actual outputs, the classical-query comparison, and simulation limitations. Explain how to reproduce the results and credit the resources used.
